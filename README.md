## ✅ 实机刷入验证

该修改版镜像**已在本机（无界 14xa / GX4HRXL / IT5571）实机刷入并测试生效**（2026-11-10）：

- 用官方 BIOS 更新包自带的 `IFUX64.EFI` 在 UEFI Shell 下写入 `0x00000–0x3FFFF`，刷写过程返回 `Verify OK`，刷后正常开机；
- **充电电压可现场观测**：在**机械革命官方控制中心里切换电池充电模式**时，可以直接看到充电电压随模式变化 —— 对应本补丁把每芯降额改成 0 / 100 / 200 mV 后，4S 目标电压为 **17600 / 17200 / 16800 mV** 三档（实测读数会随充电电流与线损有小幅浮动，趋势与档位一一对应即可）；
- 三档性能模式（`Fn + X`）的风扇转速曲线按本仓库设计值生效；
- 电池容量学习不再受原厂「每轮 ±300 mAh」限速，改由 3500–5700 mAh 窗口守卫兜底。

> 自己复现观测：进官方控制中心 → 依次切到三个电池模式 → 记录充电电压；或直接用 EC 寄存器读取工具看 `EC[0x07A6]` bits[5:4] 与目标电压 `XRAM[0x0522:0x0523]`（LE，单位 mV）。

## 🔧 修改版 EC 做了什么（相对官方 EC-V14.6_A）

共 **649 字节 / 56 簇**差异（占整片 0.25%），PD 固件（`0x20000` 起）1 字节未动：

| # | 改动 | 落点 |
|---|---|---|
| 1 | **电池容量学习提速**：取消原厂「每轮最多 ±3 factor（±300 mAh）」限速，改为**绝对窗口守卫**（只采纳 3500–5700 mAh，越界则保持原值） | `0x14974` + 代码洞 `0x7E6A–0x7E80` |
| 2 | **充电限压档位**：原厂五档（250/200/150/100/50 mV per cell）→ 按 BIOS 模式位直接取 **0 / 100 / 200 mV per cell** | `0x1D303–0x1D31D`（27 B 原地替换） |
| 3 | **忽略 AP 存在性检查**：AP 不在线时不再清掉 BIOS/GCU 写入的充电模式位 | `0x1D1D7–0x1D1DB`（5 B） |
| 4 | **风扇三档曲线自定义 + 副风扇表全部同步主风扇** | `0x6D05–0x6F74`、描述符 `0x716D–0x7190`、新增副表 `0x7E90–0x7FB0` |

### 充电电压档位（4S，基准 17600 mV）

| `XRAM[0x07A6]` bits[5:4] | 语义 | 每芯降额 | 目标电压 |
|---|---|---|---|
| `0x00` | Normal / 默认 | 0 mV | 17600 mV（4.400 V/芯） |
| `0x10` | Balanced | 100 mV | 17200 mV（4.300 V/芯） |
| `0x20` | Health | 200 mV | 16800 mV（4.200 V/芯） |

### 风扇三档曲线（`Fn + X` 切换）

| 模式 | 温度 → 占空比 |
|---|---|
| 静音 | ≤36 ℃ 0% ｜ 37–44 ℃ 25% ｜ 45–49 ℃ 35% ｜ 50–69 ℃ 45% ｜ ≥70 ℃ 60% |
| 均衡 | ≤34 ℃ 0% ｜ 35–39 ℃ 30% ｜ 40–44 ℃ 35% ｜ 45–49 ℃ 40% ｜ 50–59 ℃ 45% ｜ 60–69 ℃ 50% ｜ 70–79 ℃ 80% ｜ 80–84 ℃ 90% ｜ ≥85 ℃ 100% |
| 性能 | ≤34 ℃ 0% ｜ 35–39 ℃ 30% ｜ 40–44 ℃ 35% ｜ 45–49 ℃ 40% ｜ 50–59 ℃ 50% ｜ 60–69 ℃ 65% ｜ 70–79 ℃ 85% ｜ 80–84 ℃ 90% ｜ ≥85 ℃ 100% |

三种模式各对应 3 套主板表（base A / B / C），本机到底用哪一套无法离线判定，因此 9 张主表全部改；副风扇 9 组描述符全部指向与本模式主表**逐字节相同**的副本（校验：16 档 × 9 组合 = 144 点全一致）。

## 💾 刷入方法（本人实测方式）

用官方 BIOS 更新包里自带的刷写器 `IFUX64.EFI`，在 UEFI Shell 里刷：

```text
fs0:
cd \ecflash
ifux64.efi ec.bin 0 1
```

- 刷前：BIOS 里关闭 **Secure Boot**、插上电源适配器、电量 > 30%；
- 只写 `0x00000–0x3FFFF`（256 KiB），**不要整片擦除**；`0` = 从偏移 0 写入，`1` = 刷完复位；
- 出现 `Verify OK` 即成功；刷写过程中键盘失效属正常（EC 进入 Follow Mode）。

**回滚**：把 `bios-unpacked/EC_ITE_EC-V14.6_A_PDV0.27.bin` 用同样命令写回（`ifux64.efi official.bin 0 1`）。

**刷后校验**（Linux 下 `ec-flash --dump` 或编程器读回后）：

```bash
sha256sum dump.bin
# 前 256 KiB 应等于：69104481f6a6cf3e8878bcf2c5158cac8dd35a52286f1ac79d871f5e95a288e5
```

## 🧪 证据与风险

- 所有改动均为对二进制**逐条反汇编解码 + 字节比对**得出（D1）；「本机用哪套风扇表」「BIOS 何时写模式位」等属于代码语义推断（D2）。
- 容量学习取消限速后，异常的完整学习循环可能让 FCC/电量显示跳变（已用 3500–5700 mAh 窗口兜底）。
- 刷 EC 有变砖风险：**写入中断电可能导致无法开机**，只能拆机用 CH347/CH341 夹 SOP8 闪存救回。风险自负。
